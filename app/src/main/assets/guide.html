Cookie Extractor

Extract your own session cookies after logging in by hand, then share them with any app or script that needs an authenticated session.

Quick start

  1. Type the site address in the bar and press Go.
  2. Log in exactly like in a normal browser: password, 2FA, OTP, or an SSO redirect flow.
  3. Tap the round share button at the bottom right.
  4. Pick where to send the cookies: a messaging app, the clipboard, a note.

Nothing leaves the phone until you choose a share target.

Structured share (the envelope)

The share button sends a version-2 JSON document with cookies from the loaded page plus every configured extra domain (see below). The overflow menu entry Switch to flat cookies changes the share to the legacy single-domain cookie string.

{
  "version": 2,
  "cookies": [
    {"name": "SID", "value": "...", "domain": ".example.com"}
  ]
}

Sharing from a slack.com page while a workspace client is signed in adds a slack field with one entry per team (team_id, enterprise_id, team_name, xoxc). It is simply absent when there is no signed-in session.

Extra domains

Overflow menu, Extra domains: the list of domains the structured share collects beyond the loaded page.

  • One URL or bare host per line; lines starting with # are comments.
  • Bare hosts get https automatically.
  • The default list is the Google family; Reset to default restores it.
  • An empty saved list is deliberate: it means collect from the loaded page only. Delete the rule and reset if you want the default back.
# one URL or bare host per line
https://git.example.com
git.mycompany.com     # bare hosts get https
accounts.google.com
# an empty saved list means: loaded page only

Share template

Long-press the share button to open the template editor. The template shapes the text both shares send. Leave it empty for the default message.

TokenBecomes
{payload}the cookies (or captured tokens)
{url}the page URL
{title}the page title
{host}the page host
{date}today, ISO-8601

Example: with this template,

curl -H "Cookie: {payload}" {url}

a payload of a=1; b=2 on https://example.com/ shares:

curl -H "Cookie: a=1; b=2" https://example.com/

Unknown tokens stay as written. The session monitor, the debug channel, and the agent API are documented in the project README.
